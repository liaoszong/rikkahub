## 🧠 PaleInk RikkaHub 智能上下文与长期记忆升级

PaleInk RikkaHub 2.4.5-pale.7 重点升级了长对话、联网搜索、长期记忆和中断恢复能力。新版本不再只按“消息条数”粗略截断上下文，而是根据不同模型的真实 token 窗口，在系统指令、当前问题、工具调用、搜索证据、记忆、摘要和旧对话之间进行可解释的预算分配。

### 🧩 长对话与上下文引擎

- 上下文改为按 token 预算编译，系统指令、当前用户消息和 Provider continuation 会被强制保留。
- 工具调用与工具结果作为完整语义单元选择，避免只留下半段调用或孤立结果。
- 最近对话、结构化摘要、长期记忆、搜索证据和旧历史按稳定优先级装入窗口；预算不足时会明确排除低优先级内容。
- 压缩摘要现在保留来源消息引用，原始对话和分支仍是权威数据，不再为了压缩而破坏性替换历史。
- 增加 Context Manifest，可记录本次请求包含、排除和转换了哪些上下文，为后续诊断和质量评估提供依据。

### 📐 不同模型使用真实上下文窗口

- 直接连接 ChatGPT/OpenAI API 时，GPT-5.4、GPT-5.5、GPT-5.6 Sol/Terra/Luna 使用对应的 1.05M API 上下文窗口。
- PaleInk 供应商通过 Codex 引出的兼容 API 提供模型，因此独立采用 Codex 的 272K 通道窗口，并在 5% 安全空间后按约 258.4K 有效边界规划。
- PaleInk 内置模型即使来自旧版本配置，也会在启动时补齐 Codex 通道上限；相同模型 ID 不会再把 OpenAI API 与 PaleInk 的窗口混为一谈。
- 自定义 Provider 可在模型高级设置中覆盖上下文窗口；未知模型才使用 128K 安全兜底。
- 仍会预留 5% 安全空间、模型最大输出以及搜索修复空间，降低长请求在 Provider 端溢出的概率。

### 🔎 Web Search 可靠闭环

- 搜索结果改为结构化证据，统一保存标题、来源、URL、引用标识、可信状态和截断信息。
- OpenAI、Gemini、Claude 及搜索工具的结果进入同一套证据和引用管线，复制、导出、Android 与 Web 显示保持一致。
- 搜索已经取得结果但模型未生成最终回答时，会进入受限的最终综合阶段，禁止再次搜索或调用其他工具。
- 增加搜索步数上限、终态检查和失败原因记录，减少“搜索完成后没有回复”以及循环搜索。
- 外部网页内容默认按不可信证据处理，不能静默触发写入、执行或其他有副作用工具。

### 🧠 Memory V2

- 长期记忆增加稳定身份、助手/全局作用域、来源、来源可信度、置信度、状态和时间信息。
- 新记忆保留来源对话或用户显式操作，可撤销、更新并追踪冲突，不再只是无法解释的一段文本。
- 记忆检索与上下文预算联动；记忆关闭或隐私策略禁止时，不会读取或发送长期记忆。
- 旧版记忆通过数据库迁移保留，并继续兼容原有助手配置。

### 🔄 中断恢复与连续性

- Provider continuation、工具结果和最终回答使用持久请求账本衔接，已提交输出会先持久化再继续下一步。
- App 中断后可区分尚未发送、结果未知、结果已收到和已经提交，避免把所有异常都当作可安全重试。
- 搜索综合、工具执行和多段模型响应具有明确终态；超过限制会给出可诊断失败，而不是无限循环。
- 新增任务与质量状态入口，为后续后台任务、跨设备连续执行和文档工作流提供统一基础。

### 🔐 隐私、可观测性与产品收口

- 新增联网、长期记忆、本地优先和匿名质量指标开关；隐私策略会在实际 Provider、搜索和记忆入口执行，而不只是界面状态。
- 质量指标只记录模型族、终态和诊断类别等最小信息，不保存用户提示词、搜索正文或凭据。
- 引用、搜索证据和日志继续清除鉴权信息、敏感查询参数及不应离开设备的内容。
- 同步吸收了上游近期的模型识别与兼容改进，同时保留 PaleInk 自己的请求账本、媒体、引用和隐私边界。

这次更新的核心目标，是让对话变长、工具变多、搜索链路变复杂以后，App 仍然知道哪些内容必须保留、哪些结果已经提交、哪些记忆来自哪里，以及中断后应该从哪里安全继续。
