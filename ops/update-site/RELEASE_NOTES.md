## 🧱 PaleInk RikkaHub 长期稳定基座

PaleInk RikkaHub 2.4.5-pale.6 是面向长期使用的一次大型可靠性升级。它集中修复切到后台后聊天中断、图片已经生成却无法回填、旧图片升级后显示未完成，以及异常恢复可能重复执行请求等问题；同时重构会话、媒体、请求、凭据和引用的底层存储，为后续语音、项目文件、任务中心和跨设备同步提供稳定基础。

> pale.5 仅作为内部开发阶段，没有公开发布。pale.4 用户可直接升级到 pale.6。

### 🚑 后台聊天与请求可靠性

- 📱 普通聊天、工具调用和图片生成共用真实的前台服务。发送后切到其他页面或让 App 进入后台，长响应不再因为页面生命周期结束而被主动断开。
- 🔄 每次 Provider 请求、工具调用和付费图片槽位都有稳定身份与持久状态；App 被系统终止后可以解释请求停在哪一步，而不是只显示笼统的“生成失败”。
- 💳 已经发送、但结果未知的付费或有副作用请求不会自动重放；图片生成接口也关闭透明网络重试，降低断线时重复请求和重复计费风险。
- 🧩 文件已经保存、但数据库登记中断的结果会在启动时进行本地补登记，不会再次请求模型。
- 🛑 取消、重新生成和并发会话按精确任务归属处理，旧任务结束不会误清除或停止新任务。

### 🖼️ 图片生成、编辑与图片库

- 💬 图片生成和参考图编辑继续统一从聊天发起；“图片库”只作为汇总各对话生成图片的跨会话相册，不再维护第二套生成任务。
- 🪄 一次请求 1–8 张图片时会拆成独立的单图槽位；哪张先完成就先落盘并展示，其他位置继续显示生成中，单张失败或取消不会抹掉已经完成的图片。
- 🏞️ 修复旧版工具输出升级后只显示“图片生成未完成”的兼容问题。只要原文件仍在本机，历史图片会重新出现在对话和图片库中。
- 🧯 旧版图片 sidecar 与迁移后的图库记录即使稳定 ID 不同，也会以已提交记录为准完成恢复；占位记录可在任务元数据稍后恢复时补齐，单个坏文件不会再阻塞后面的图片。
- 🧬 生成图片拥有稳定资产身份，记录来源对话、模型、多张参考图和编辑关系，为连续编辑与版本链提供可靠依据。
- 🗂️ 会话删除不再误删仍应保留的图库原图；受管理文件、外部文件和临时文件使用不同的删除边界。
- 📦 WebDAV/S3 备份现在包含生成图片目录，并校验文件清单、大小和摘要，避免恢复后出现数据库有记录但图片缺失。

### 💬 长会话、搜索来源与导出

- 🧱 会话消息、分支、工具结果和媒体引用改为可恢复的增量存储，降低超长消息、频繁保存和异常退出造成历史缺口的风险。
- 🔎 OpenAI、Gemini 和搜索工具返回的来源采用结构化引用；Android、Web、复制和 Markdown 导出共用同一组标题、链接、引用位置与可用状态。
- 🧹 引用元数据会限制大小并清除鉴权信息、Token 和敏感 URL 参数，旧格式引用会在后台安全迁移。
- 🔍 全文索引通过持久队列更新，异常中断后可继续补齐，不再依赖一次性内存状态。

### 🔐 凭据、工具与备份安全

- 🔑 Provider、MCP、搜索、语音、WebDAV、S3 和 Web 服务凭据迁入 Android Keystore 保护的设备凭据库；普通设置只保存不可用作密钥的稳定引用。
- 🛡️ 凭据轮换、OAuth 更新和升级迁移采用可恢复流程。若设备密钥不可用或损坏，App 会停止相关联网能力并要求重新输入，不会回退到明文秘密。
- 🧰 MCP、Workspace 和本地工具统一使用权限、审批与执行记录；新发现或结构发生变化的 MCP 工具不会自动获得旧授权。
- 📦 备份使用一致的 Room 快照、安全 ZIP 路径和展开上限，并在校验完成后原子恢复；默认导出继续排除秘密。
- 🌐 Web 服务默认只监听本机；局域网模式要求有效认证，文件接口只能访问已登记的受管理文件。

### 🤖 Provider 与界面一致性

- 🧠 OpenAI Chat Completions/Responses、Gemini、Claude 和兼容 Provider 共用版本化的模型能力快照，统一决定附件、图片生成/编辑、工具、推理和协议参数。
- 🚫 背景标题或建议不会静默跨到另一家 Provider；多 Provider 场景下无法安全确定目标时会明确停止。
- ⚡ 展开图片画廊不再同时绘制新旧两张大图或对整条消息持续做尺寸动画；右侧快速跳转按钮只在用户实际高速滚动期间出现，慢速、停止、边界和程序化滚动都立即隐藏。

### 🔄 升级说明

- 首次启动会显示安全恢复页，并在后台校验、复制和提交会话、媒体、请求、凭据与引用数据；历史很多时可能比平常稍久，但不会在主线程执行大文件哈希或复制。
- 文件与设置必须共同提交后，Room、聊天界面和后台任务才会开放。恢复失败时 App 保持关闭状态并提供重试；即使进程中断，也会根据持久日志先完成回滚或继续恢复，不会打开半迁移数据。
- 若上次启动或运行时初始化异常，App 会先进入隔离的安全模式；确认继续后通过冷启动重新执行完整初始化，不会在半初始化进程里直接开放聊天或恢复付费请求。
- 建议升级前先完成一次 WebDAV 或 S3 备份。升级后可检查一条历史长会话、图片库和常用 Provider 凭据是否正常。
- pale.6 已包含加密、冲突检测和对象传输的 Sync v2 底座，但本版本**尚未开放跨设备实时同步**；现有 WebDAV/S3 仍以安全备份与恢复为主。
- 若旧图片文件曾被系统清理、手动删除，且备份中也不存在，App 会明确显示“本地文件缺失”，无法仅凭数据库记录还原原图。

这次升级的重点不是增加另一个入口，而是让已经存在的聊天、图片、工具和备份能力在长时间、后台、异常退出和版本升级后仍然可信。
